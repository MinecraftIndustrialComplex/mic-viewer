# Choices made while building the viewer

Reversible choices taken while building mic-viewer and its consumers (mic-rtsim's `rtsim-cli view`
and `run`, Deep Time's workbench), with why. The design they implement is mic-rtsim's VIEWER.md, its
proposals VWD-1 to VWD-18 approved as recommended (DECISIONS.md BR-VWD). Anything that is Ben's call
is under "For Ben" at the end, the recommended option first.

| Id | Choice | Why |
|---|---|---|
| VC1 | The page's scripts are classic scripts that add to `globalThis.MicViewer` (and to `module.exports` under node), not ES modules as VIEWER.md §3.1 sketched. | Deep Time's workbench loads its scripts as classic `<script>` tags sharing globals (`window.DTWB`); modules would force its page to change shape. Classic scripts still need no build step, and node's test runner loads them. |
| VC2 | The web files live inside the crate (`crates/mic-viewer/web/`), not at the repo root. | `include_str!` then works when a consumer vendors the crate folder alone (VC4). |
| VC3 | The crate's Cargo.toml is self-contained: no workspace inheritance. | Same reason: the folder builds on its own inside another workspace. |
| VC4 | Deep Time vendors `crates/mic-viewer` at a pinned commit (`vendor/mic-viewer/`, the commit in `vendor/mic-viewer/PINNED`, refreshed by Deep Time's `tools/dev/refresh-mic-viewer.sh`) instead of a git dependency. mic-rtsim pins it by git rev, as it pins mic-native. | Deep Time's builds and tests run on its Azure VM, which cannot fetch private GitHub repos (publickey denied). See "For Ben". |
| VC5 | The square tile pyramid's zoom 0 is one block a pixel and zooms go negative outward (zoom -6 is 64 blocks a pixel); tile indices are signed and unbounded. | Vanilla worlds have no frame to fit a zoom 0 into; block-aligned tiles make every tile's blocks exact. Deep Time's 2:1 pyramid stays its plug-in's. |
| VC6 | A published view is a `Scene`: immutable, one per publication, each layer's marks indexed by 512-block region with counts. A mark whose box covers more than 64 regions is kept on a list every query checks. The parts' binary form for the live tap's pages is left to V4. | The save and host sources build scenes in process; only the live tap needs bytes on disk, and its format is best fixed with the tap. |
| VC7 | The 2,000-mark budget is shared by water filling (each layer is offered an equal part; a layer that needs less takes only that; the remainder goes to higher priority first). A shape smaller than a 32 px bin bins like a point; larger edges, paths and areas keep the largest when over their share. | No visible layer starves another, a quiet layer always shows everything, and 100,000 district boxes at a distance become honest clusters rather than the 379 largest. |
| VC8 | Layer versions are a 53-bit hash of the layer's marks, not a publication counter. | The page refetches only layers whose marks changed; an unchanged layer costs nothing per publication. 53 bits so JavaScript holds them exactly. |
| VC9 | The stream's `frame` event also carries each frame's layer versions (`frames`). | The page compares against what `/api/marks` returned for its own frame. |
| VC10 | A viewer over a save caches tiles in memory, never in the world's folder (`TileCache::in_memory`); Deep Time keeps its disk cache under the run's folder. | V1's exit test: the save folder's bytes are unchanged. |
| VC11 | The repo has a synthetic demo world (`crates/mic-viewer-demo`) served through the same routes. | The page needs a fixture with every mark kind, a wrapped frame, history and a moving clock for development, screenshots and the browser smoke test; the budget test needs 100,000 districts. |
| VC12 | A tile source answers `TileError::Missing` (404, and the page never asks for that tile again) or `TileError::Failed` (500, asked again later), not one error. | A layer the bake lacks or an index past the pyramid is permanent; a read that failed is not, and caching it as missing would leave a hole until reload. |
| VC13 | `tiles::serve(source, cache, immutable, rest)` is a free function beside the `Tiles` pair. | Deep Time keeps one source and one disk cache per run inside its own workbench state; it serves tiles without wrapping each run in a `Backend`. |
| VC14 | The server sends `Referrer-Policy: same-origin`, not `no-referrer`. | Under `no-referrer` browsers send `Origin: null` on the page's own POSTs (Deep Time's workbench starts runs by POST), which the server's same-origin check must refuse. `same-origin` still sends nothing to other sites, and the page loads nothing from them. |
| VC15 | The crate carries its own `rustfmt.toml` (edition 2024, width 120, `use_small_heuristics = "Max"`) in its folder, not the repository root. | A vendored copy keeps this style under the consumer's `cargo fmt --all --check` (rustfmt reads the nearest config), so Deep Time's width-100 style never fights it. |
| VC16 | Deep Time's Final world view is a plug-in over `createMap`: its `worldmap.js` turns the run's `world.json` into the core's projection and 2:1 pyramid (`DTWorldMap.frameOf`) and keeps its layers, grid, readout and preview box; the grid and the preview box draw through the core's `overlays` hook. Deep Time's `tools/viewer/worldmap-check.js` holds the core to the old view's tile zoom and tile placement (2,400 random views, three planet sizes, both projections). | VW3: the core moves, the projection, tiles and parity test stay Deep Time's. The parity check is what makes the move safe: the core must draw exactly the tiles the old loop drew. |
| VC17 | The map core fetches tiles with `fetch` and `createImageBitmap`: 204 is an empty tile (never asked again, nothing stands in), 404 a missing one (never asked again, the nearest loaded ancestor stands in), any other failure is retried after 4 s. Smoothing turns off once a tile pixel covers 1.75 device pixels; a flat world zooms out to twice its fit and home is 1.06 times the fit. | One request per tile for the page's life on a potato PC (D1); magnified tiles stay crisp blocks; the whole world fits with a margin. |
| VC18 | The map core's API grew past VIEWER.md's sketch: `copies(x, pad)`, the screen position on `onHover`, a per-layer `pyramid`, `bounds` and `visible`, `setBackground`, `setScaleBar` (with a theme's `ink` and `halo`), `stats()`, `idle()`, getters for `cursor`, `projection` and `pyramid`, and `view` and `start` options. docs/map-core.md is the API as built. | What the page, the smoke test and Deep Time's plug-in needed; each is additive. |
| VC19 | Marks: a point's size is its diameter; labels draw last and never overlap; a click on a cluster zooms in 3 times on it; the marks request's box is the view padded by 25 %; only changed layers are refetched, and only when no held layer is clustered; version changes are ignored while looking at the past. | Small pans cost no request; the past stays still while the present moves. |
| VC20 | Page defaults: tile layers start with every overlay and the first base layer on; the layer panel starts open on a desk and closed on a phone, the timeline closed; dark unless the system prefers light; the theme, the timeline's span and its hidden kinds are kept per viewer in local storage. | The map is the first thing seen; the choices a viewer makes survive a reload. |
| VC21 | Cards: a click on empty map closes the card; Enter or Space on the map opens what is under the pointer; the address's hash carries `card=layer/id` beside the view, so a card is a link. | Keyboard parity with the mouse; links to a thing, not only to a place. |
| VC22 | Timeline: histogram buckets are the strip's width / 5, clamped to 24 to 360; the list shows t +/- 1.5 buckets (at least a game hour), or the last game day when live; event markers draw only while the timeline is open, and a picked event stays marked until it closes or the frame changes; flying to an event ends at most 4 blocks a pixel and is instant under reduced motion. | Bars stay readable at any width; the map is not cluttered by events nobody asked for. |
| VC23 | Stream `events` rows carry an optional `frame` (none: the world's first frame); the page lists and flashes a row only in its frame, and `/api/events?frame=` answers per frame. | Before it, the page dropped every live row outside the first frame, since it could not tell where a row happened. Optional and skipped when none, so a single-frame source sends what it sent before. |
| VC24 | Base map descriptors carry optional `default_on` and `alpha`; the viewer's saved choice still wins, then `default_on`, then the old rule (first base map and every overlay). | The page guessed which base maps to show and drew them opaque; a source knows better (a heat overlay at 0.6, a second base map off). |
| VC25 | The demo has a third clock, `--stepped TICKS [--every MS]`: each publish moves the world TICKS ticks, so the world and its stream messages after n publishes are the same on every run. The smoke test runs a second, stepped demo for live updates, and waits for the page to be loaded (no request pending) rather than idle there, since a live world animates its caravans every frame. | `--still` sends only hello and pings, so nothing covered `frame` and `events` end to end; the wall clock is not repeatable. The demo also publishes ring-frame events, so VC23 has a fixture. |
| VC26 | `rtsim-cli export` (the fork copy through the read-only open) is built in V2 with `rtsim-cli run`, not in V1; V2 starts beside V1 on its own branch (`feat/viewer-host`, cut from V1's `feat/viewer`) and adds the host source last, over V1's backend. | `run` is export plus a host, so one owner writes the copy once; V2 needs nothing of V1's but the read-only open, already committed, so the two run in parallel with no shared files but rtsim-cli's dispatch. |
| VC27 | Deep Time keeps its vendored core at eb4af9c after VC23 to VC25: it builds none of the structs they changed. | Refreshing would cost a page test cycle for no change in the workbench; `tools/dev/refresh-mic-viewer.sh` brings it up when the workbench needs a newer core. |
| VC28 | The Surveyor reader and renderer are their own crate here (`crates/mic-viewer-surveyor`, MPL-2.0, flate2 its one new dependency), not a module of mic-rtsim's `rtsim-view`; it lands now as a library, ahead of V5, while V1 and V2 hold mic-rtsim's viewer files. V5 itself (the layer in `rtsim-cli view` over HABITAT, its exit test on the MICTest save) still lands after V3 and V4. | Surveyor is a pack mod, not rtsim: any MIC tool over a world can draw it, and rtsim's workspace stays free of NBT. It touches nothing else in this repo. No code came from Surveyor (LGPL-3.0-or-later): its classes were read for the file layout only, and the layout is documented in VIEWER.md §9. |
| VC29 | How the Surveyor map draws: the floor block's default map colour (what Surveyor stores); grass and leaves in the biome's grass and foliage colours only when Surveyor recorded one, since a dedicated server has no colour maps and records 0 for every biome without an override; relief from the step to the block north (0.9 flat, 0.045 a block, clamped at 5), reading the northern region's south row across the seam; water mixed over the floor by depth (biome water colour, 55 % at one block, 90 % from eight) and darkened to 65 % at 24 blocks; unrecorded columns transparent so the base map under it shows; the top band's floor (the Nether skips floors above y 126, its bedrock roof). Zooms 0 to -6 (TUNABLE); a 64 MiB picture cache (TUNABLE) holding each region and its halvings; a corrupt region fails its zoom-0 tiles (500, asked again) and is left out of coarser ones. The layer's bounds are the largest cluster of regions at most 64 regions apart (TUNABLE). | Vanilla's map look, but with biome water and smooth relief; measured on a copy of a dedicated server's world, 123 regions in 1.7 s on one core (14 ms a region). The cluster rule keeps far regions (12 near region 40,000 in the MICTest save, beside its `sublevels` folder: Sable's, it seems) and lone trips from setting the map's extent. |
| VC30 | The archive's format and folder are a library crate in mic-rtsim (`crates/rtsim-archive`, branch `feat/viewer-archive`), built ahead of V3's hooks while V1 and V2 hold the viewer and host files. Byte 9 of a row holds the severity (bits 0 to 2), then leg, subject-in-dictionary, object-in-dictionary, clamped and payload flags; legs carry a severity too, a named mover's legs notable, so the notable tier's filter is one comparison. Past the pending cap the oldest rows of the lowest severity go, an eighth of the cap at a time, and a row less severe than everything held is dropped itself; payloads count against the 1 MiB, and one on a row below notable or over 16 KiB (TUNABLE) is dropped and counted, its row kept. A chunk header counts rows per frame and kind (the histogram route answers per kind for one frame), and also keeps the furthest leg end and the save's game tick beside its wall clock (the dates under game days). The index is the truth: the writer deletes chunk files it does not name on open, rebuilds an unreadable index from the chunks' own headers, and clears the archive when the dictionary is unreadable (`was_reset`); nothing is fsynced. The histogram spreads a chunk's counts evenly over its tick span. | Orphan chunks can only be a flush that never reached its page commit (the rollback would cut it) or an unfinished compaction (its rows are still in the chunks it replaces), so deleting them is always right, provided V3 finishes the flush (chunks, then index) before the page commit. Guessing kind numbers after losing the dictionary would mislabel every row; the archive is a record, not the truth (§10.3). The furthest leg end lets "who was where at tick t" read only the chunks that can hold a covering leg. |
| VC31 | V1 (mic-rtsim `feat/viewer`) stays pinned at mic-viewer 01c9595; V5 moves the pin to 8ed7a99 with the Surveyor crate at the same commit. | 01c9595 to ef3c512 changed nothing under `crates/mic-viewer/src`, so V1 needed no bump; one bump when a consumer needs the new crate. |
| VC32 | rtsim-view keeps its own copy of where each module keeps its pages (`keys.rs`), checked by a test against the native link's exported values. | rtsim-view cannot link rtsim-jni (a cdylib with JNI); a mirrored table with a test fails loudly when a key moves. |
| VC33 | A save's scenes are built once, at open; a request for any `t` gets the save's scene. | A save does not move; the past is the archive's (V3), not a replay. |
| VC34 | V1 builds scenes straight from the decoded save; the part format (VIEWER.md §4.3) moves to V4, when a second producer (the live tap) first exists. | A format with one producer and one reader is a guess; V4 designs it against both. |
| VC35 | Frames are flat with no wrap: the pages hold no topology. | Deep Time worlds draw without seams until Ben picks where topology comes from (For Ben 2). |
| VC36 | Dimension and district names come from Java's `data/mic_rtsim_journal.dat`; without it a frame is `dim<id>`. | The pages hold numbers only (For Ben 3). |
| VC37 | The price layer is off by default. | It covers every market and hides the map; ops turn it on when they ask about prices. |
| VC38 | Messengers are the news packets on roads; hunts are their own layer, a line from the dragon to its target. | That is what each module's state holds; nothing is invented between saves. |
| VC39 | Built cards are cached least recently used out, sized by JSON bytes, up to 256 MiB (TUNABLE, `--card-cache`). | A district card rebuilds an engine from three pages (3 to 4 ms); repeat clicks should not. |
| VC40 | One worker lock covers card builds and tile renders (VWD-15), Surveyor's included. | The sidecar uses one core of work at most, at idle priority (D1). |
| VC41 | The decoded save sits behind a mutex. | Paged rows cache through `RefCell`s and are not `Sync`. |
| VC42 | Industry keeps only its globals and a small summary per district; each district card rebuilds an engine from three pages. | 100,000 synthetic districts open in 0.8 s with a 32 MiB heap (53 MiB peak while reading), against a 1,024 MiB cap. |
| VC43 | HABITAT tile layers are named `habitat-<slug>`, zoom -10 to -4, served no-cache. | 64-block cells need nothing finer; no-cache because a later save of the same world changes them. |
| VC44 | An empty layer's reason goes in `/api/status` and on the layer's description (superseded by VC54). | mic-viewer has no field for it yet (`LayerMarks.empty`, under "Left" in the final report). |
| VC45 | Game ticks everywhere in the API, as Deep Time's play time is. | One clock across sources; the page formats days. |
| VC46 | The sidecar's memory cap is 1,024 MiB by default (`--mem-cap`): a save over it is refused at open, district cards once the heap reaches it. | Ben was away; taken as V1 recommended. Measured far under it on the largest bench world. |
| VC47 | A layer is all or nothing: a builder that panics (a page compacted away under the reader) leaves the layer empty with its reason. | A half-drawn layer would look complete. |
| VC48 | The save viewer's `stream` flag is off. | A save never changes; the page polls nothing. |
| VC49 | `rtsim-cli view` is its own module with a one-line dispatch arm in `main.rs`. | Keeps V2's `run` and `export` from colliding with it. |
| VC50 | `/api/status` shows no filesystem path; the world is shown by its folder's name. | VIEWER.md §13: an answer forwarded over SSH should not reveal the host's layout. |
| VC51 | `rtsim-cli view` exit codes: 1 the save does not open or is over the cap, 2 the server cannot start, 64 usage. | Scripts can tell a bad world from a busy port. |
| VC52 | Surveyor draws over HABITAT, both on by default, in each frame named by a dimension (`minecraft:the_nether`); a frame known only by number has no folder to look in and keeps HABITAT. The tile cache is halved between the two maps when both are there; Surveyor's pictures share `Limits::surveyor_cache` (64 MiB, TUNABLE) across frames. | Surveyor leaves unrecorded columns transparent (VC29), so HABITAT's coarse cells show where nobody has been; halving keeps the sidecar's memory where it was. |
| VC53 | The archive reader skips and counts a chunk damaged after indexing instead of failing the request; `ArchiveReader::newest` answers `/api/events` reading chunks newest first and stopping at the first too old to matter; the kinds the recorders write and the page shows live in one registry in the archive crate (`rtsim_archive::kinds`), the page's group being the name's part before the dot. Archive frame names are `dim<n>`, the engine's numeric dimension, which the viewer turns into the dimension's name; payloads are one line of UTF-8 text the page shows as the row's text; subject or object 0 is none. | One bad file should cost the page its rows, not the timeline; a 300-row list over years of history should read a few chunks; one registry keeps labels and names from drifting between the engine and the page. |
| VC54 | A layer that drew nothing says why in the answer itself: `LayerMarks.empty` (set through `SceneWriter::empty`; any mark wins over the reason), shown under the layer's name in the panel. This replaces VC44's description suffix. `Backend::budget` (default `MARK_BUDGET`) lets a backend answer with fewer marks; `Mark::with_id` and `Card::as_of` are small builders the rtsim adapter needed. | The reason belongs beside the marks it explains, and it changes with the save, which a layer description does not; a slow source on a potato PC can lower its own budget without forking the core. |
| VC55 | `/api/stream` answers 204 No Content when the backend's `changes()` is `None`. | EventSource retries an error or a closed stream every few seconds forever, but stops on 204; a save never publishes. |
| VC56 | A request handler that panics answers 500 and frees its connection slot (`catch_unwind` and a slot guard). A Unix socket is chmod 0600 after bind; `start_unix` refuses (AddrInUse) when a live server answers on the path and removes only a stale socket. | 64 slots leaked one panic at a time would wedge the server; on a shared host the socket file's mode is the access control, and a second sidecar must not take over a running one's socket. |
| VC57 | A V1 session is a snapshot of the one save it opened. A module whose pages panic while loading is Unreadable with its reason (loads run under `catch_unwind`); a district card whose pages have gone since (compaction under a running world) says so, tells the reader to restart the viewer to see the new save, and is not cached. | Reopening under a running session would mix two saves in one answer; following a running world is V4's live source. |
| VC58 | Card ids are canonical: a numeric id is parsed and printed again before the cache lookup (`007` is `7`). | One cache entry per thing, and a hand-typed URL gets the same card. |
| VC59 | Every text an answer carries from a module (Unreadable reasons, the missing-name list, layer reasons, card notes) has the world's absolute path replaced by the folder's name where it is made. Extends VC50. | Error texts from the page store name files by absolute path; §13 says no answer reveals the host's layout. |
| VC60 | `rtsim-cli view` checks its bind address before reading the save and refuses a Unix socket inside the world folder, both exit 2; `--surveyor-cache MiB` sizes Surveyor's pictures. Write methods answer 405 and HEAD answers headers only, tested. | A refused bind should not cost a save's open; a socket in the world folder would be a write into the world (VWD-11). |
| VC61 | rtsim-view opens the world's archive read only as of the save it read (`ArchiveReader::open(dir, Some(obs_seq))`), so chunks a later save flushed are not shown beside older pages; the archive's frames (`dim<n>`) join the world's frames under the journal's dimension names; WorldInfo's `has_events` and `event_kinds` come from it, and a save without an archive has no timeline (mic-rtsim `feat/viewer-events`). | The timeline must agree with the scene it sits beside; a frame that only the archive knows still needs a name. |
| VC62 | V1's Windows exit test moves to V4. | A V1 session holds no file open between reads; V4's live reads are the harder case, and Windows is not runnable here yet. |
| VC63 | V5 landed on mic-rtsim main (03c1738) right after V1, ahead of V2, V3 and V4, together with the archive crate and the viewer's timeline over it; this replaces VC28's "V5 lands after V3 and V4". The exit run used the MICTest save's Surveyor folders beside the core GameTest pages, since no MICTest save has rtsim pages yet; screenshots in mic-rtsim `docs/viewer/`. | It was done and tested, and V4's live source should start from a main that already draws terrain and the timeline rather than merge them in later; V3 builds on the same archive commits, so its merge is trivial. |
| VC64 | rtsim-view's GameTest fixtures are replaced by fresh `./gametest.sh core create` runs whenever a page format changes on main (the money sink changed the phase 1 snapshot's magic): each fixture asserts the layers it draws, and the union with the harness world still draws all 21. | No compatibility before release; a fresh world has no caravan or herd route in flight at the stop by chance, so per-fixture lists follow the run, and the harness world covers what a run misses. |
| VC65 | The link and the viewer build the phase 1 goods and recipe book through one function (`rtsim_world::catalogue::catalogue()`), and a module whose saved state hash differs from what the viewer reads back is flagged in `/api/status` (`hash_matches: false`) and by a WARNING line at start, never refused. | Two copies of the catalogue would drift silently; a mismatch means the drawing may be wrong, which the op should see, but the rest of the world still draws. |
| VC66 | The industry engine gets `processes_peek` (each replay process at now: box or packager link, running or why stopped, power requirement), and the district card lists a district's processes and the other districts of its replay cluster (`cluster_members`). | The card should show what the replay is doing and which districts it shares running states with (I13); both through `&self` peeks, as §5.3 requires. |
| VC67 | Industry writes no state hash, so its read-back check is the harness: the iron line stops on day 3 of a ten-day plan, with three districts replaying (two in one cluster), and each card decode must equal the live engine's peeks taken just before the save. The 100,000-district viewer test joins districts four to a cluster, gives half a packager link and one in ten a station, advances the engine so replays start, and checks three cards against the engine. | A page hash only proves the bytes; comparing the decoded inspection with the engine's own catches a decode that drifts. The first 100,000-district test never advanced the engine, so its districts never replayed and its cards were trivial. |
| VC68 | A card's label column is `fit-content(60%)` and its value column `minmax(0, 1fr)`, with an 84 px floor on labels; the smoke test checks every card value keeps at least 30% of its row. The rtsim save's header time is the later of the Phase 1 and industry clocks. | A long packager or process label took the whole row and squeezed its value to a letter a line; an industry-only world showed day 0. Both are display fixes, no format change. |

## For Ben

1. **How Deep Time gets mic-viewer (VC4).** Recommended: keep the vendored copy (works today, the VM
   needs nothing, a script refreshes it). Alternative: add a read-only deploy key for mic-viewer to
   the Deep Time VM so Deep Time can pin it by git rev like mic-rtsim does.
2. **Where a world's topology comes from (VC35).** Recommended: save it in the rtsim pages (a
   TOPOLOGY page the engine writes at start), so seams and wrap draw for any world, a fork included.
   Alternatives: the sidecar reads a Deep Time world's `manifest.json` layout block through
   deeptime-format; or stay flat. The first is a page format addition, so it is yours to approve.
3. **Dimension names (VC36).** Recommended: a dimension dictionary in the rtsim pages, so a world
   copied without `data/mic_rtsim_journal.dat` (or the headless host's fork) still names its
   frames. Alternative: keep relying on Java's journal file. Also a page format addition.
4. **"Every layer draws on a GameTest save" (V1's exit test).** Taken for now: the union of the two
   GameTest saves and the headless harness world draws all 21 layers, each empty layer saying why.
   Recommended next: extend neoforge/core's GameTest so one real save sets up every module (a
   ribbit village for the touring band, a dragon hunt, a learned district). Say if the union is
   enough.
5. **The world seed.** rtsim-view copies the link's `WORLD_SEED` constant. If seeds ever become
   per world, the seed has to be saved in the pages; nothing to decide until then.
